## Design System

| Property | Value |
|----------|-------|
| Tool | none |

**Source:** codebase scout (`PageStyles.xaml`, `MainWindow.xaml`, `GamingPage.xaml`, `CheckPage.xaml`) + CONTEXT.md D-02. No web design system applies: this is a WinUI 3 desktop app, so the shadcn gate and registry vetting gate are not applicable.

**Binding rules (load-bearing, from CONVENTIONS.md):** page roots use `{Binding}` with `DataContext = ViewModel` (page-level `x:Bind` fails with WMC9999); `x:Bind` only inside `DataTemplate` with `x:DataType`; item commands live on the item class; `ToggleSwitch` rows set `MinWidth="0"`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Button/tile inner margins (`Margin="4"` in tool grids) |
| sm | 8px | Compact element spacing (section-header top margin, status footer vertical padding) |
| md | 16px | Default element spacing (`Spacing="16"`, `ColumnSpacing="16"`, card `Padding="16"`, status/footer horizontal padding) |
| lg | 24px | Unused reserve — do not invent intermediate values |
| xl | 32px | Page gutter (`Padding="32"`, `AkariPageMargin` 32,32,32,32) |
| 2xl | 48px | Major section breaks (stacked card groups may insert one 48px gap max) |
| 3xl | 64px | Page-level spacing (top hero gap only) |

**Source:** `PageStyles.xaml` (`AkariCard` padding 16, `AkariPageMargin` 32), `GamingPage.xaml`/`CheckPage.xaml` (`Padding="32" Spacing="16"`, `MaxWidth="1000" HorizontalAlignment="Left"`).

Exceptions: 2px inner title-to-description stack gap (`Spacing="2"` inside row text stacks); 12px title-bar/status-cluster gaps (`Spacing="12"`, `ColumnSpacing="12"` in `MainWindow.xaml`); 40px custom title-bar height; 232px nav pane width (`OpenPaneLength`); 200px tool-tile item width; 120px footer progress-bar width. These are fixed shell/control metrics, not spacing tokens — do not reuse them as general gaps.

**New catalog page layout contract:** `ScrollViewer` > `StackPanel Padding="32" Spacing="16" MaxWidth="1000" HorizontalAlignment="Left"`. Each of the four groups (System, Network, GPU, Background — D-03) renders as `AkariSectionHeader` + one `AkariCard` containing row grids. Row grid: two columns (`*` + `Auto`, `ColumnSpacing="16"`), left text stack (`Spacing="2"`), right control (`CheckBox` tick + state label, `MinWidth="0"` where applicable).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | Regular (400) | 1.5 |
| Label | 12px | Regular (400) | 1.4 |
| Heading | 20px | Semibold (600) | 1.2 |
| Display | 28px | Semibold (600) | 1.2 |

**WinUI mapping (use these styles, never hardcoded sizes):**

| Role | WinUI style | Used for |
|------|-------------|----------|
| Body | `BodyTextBlockStyle` via `AkariCardTitle` / `AkariCardDescription` | Row title (semibold override) + inline explanation (secondary-fill override, `TextWrapping="Wrap"`) |
| Label | `CaptionTextBlockStyle` via `AkariCaption` | Reboot-required badge text, result counts ("3 of 12 selected"), footer hints |
| Heading | `SubtitleTextBlockStyle` via `AkariSectionHeader` | Group headers (System, Network, GPU, Background), page title |
| Display | `TitleTextBlockStyle` | Page hero title only ("Gaming Catalog"), used once per page |

Exactly 4 sizes (12, 14, 20, 28) and exactly 2 weights (400, 600). No bold (700), no italic in UI copy.

**Focal point:** the page hero title ("Gaming Catalog") plus the "Apply selected" primary button in the top bar — the eye lands on the title, then the single accent action.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | System page background (`ApplicationPageBackgroundThemeBrush` / `SolidBackgroundFillColorBaseBrush`) | Window, page surface, scroll area |
| Secondary (30%) | System card fills (`CardBackgroundFillColorDefaultBrush` + `CardStrokeColorDefaultBrush`) | `AkariCard` rows, group cards |
| Accent (10%) | System accent (`SystemAccentColor`, default #0078D4, follows user/OS setting — never hardcode) | See reserved list below |
| Destructive | `SystemFillColorCriticalBrush` (default #C42B1C) | Failure states only |

**No hardcoded colors.** Every brush comes from `{ThemeResource ...}` so light/dark/high-contrast follow the OS (established in `PageStyles.xaml`).

Accent reserved for: (1) bulk-apply primary button (`Style="{StaticResource AccentButtonStyle}"` on "Apply selected" only); (2) ticked `CheckBox` check mark; (3) footer `ProgressBar` fill during bulk apply; (4) search-box focus underline; (5) `ToggleSwitch` on-state (if any row uses a switch instead of a tick). Accent is never used for body text, card surfaces, or the revert control.

Destructive reserved for: failed-row title/icon state after a stopped run + `InfoBar Severity="Error"` on apply failure. The **Revert button is NOT destructive-styled** — revert is the safe action in this product (snapshot-backed restore); it uses the default button style in the page top bar (D-16).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Apply selected |
| Secondary CTA | Revert all changes |
| Search placeholder | Search gaming tweaks |
| Empty state heading | No matching tweaks |
| Empty state body | No tweaks match "{query}". Try a different term — search matches tweak names only. |
| Loading state | Applying 3 of 12… (live count in shell status footer; indeterminate `ProgressBar` while a single row runs) |
| Success state | 12 tweaks applied (InfoBar success; ticks stay sticky per D-12) |
| Error state | "{Row title}" failed — the run stopped before applying the rest. Fix or untick it, then re-run. Details: {error message} |
| Restore-point offer title | Create a restore point first? |
| Restore-point offer body | A restore point lets Windows roll back system files if anything goes wrong. Your tweaks are already journaled for one-click revert, so this is optional. |
| Restore-point offer actions | [Create restore point and continue] [Skip and apply] |
| Reboot badge | Requires restart (inline badge on the row, does not block — D-05) |
| Destructive confirmation | None — revert is one-click with no confirmation (D-16). Revert is non-destructive by design (restores journaled prior values). No `Destructive confirmation` copy is required for this phase. |
| Progress footer | Applying {done} of {total}: {current row title} |

**Explanation block contract (BRW-02 / D-10):** every row renders its explanation inline under the title inside the same text stack — never behind an expander or dialog. Format is four short labeled lines using `AkariCardDescription` style: `What it does: …` / `Why it helps gaming: …` / `Risk: …` / `Reverts by: …`. Each line is one sentence, plain language, no registry paths (technical-details row is out of scope per REQUIREMENTS.md). Long-text wraps (`TextWrapping="Wrap"`); titles trim with `CharacterEllipsis`.

**Voice:** plain gamer language, honest about risk, never "boost" or "turbo" hype. Matches existing row copy tone ("Lower latency at the cost of stability…").

## Interaction Contract (phase-specific)

Locked by CONTEXT.md — executor implements exactly this, no alternatives:

1. **Search (D-06–D-09):** `AutoSuggestBox` in the page top bar. Matches row titles only. Suggestions from the first character. Prefix matches rank above substring matches. Tapping a suggestion filters the row list — it never jumps to or ticks the row. Cap 8 visible suggestions.
2. **Ticks (D-11, D-12):** `CheckBox` per row; bulk apply acts on ticked rows only; no apply-all button exists. Ticks stay sticky after successful apply.
3. **Progress (D-13):** existing shell status footer (`StatusService.Start/Complete` + InfoBar pairing per CheckViewModel pattern). No dialog, no inline spinners.
4. **Failure (D-14):** stop at first failure; failed row flagged, remainder untouched.
5. **Restore point (D-15):** offered via dialog before apply with Skip path; apply never blocked on it.
6. **Revert (D-16):** single one-click `Revert all changes` button in the page top bar, default button style, no confirmation.
7. **Reboot badge (D-05):** inline `Requires restart` caption badge on the row; rows are not segregated and never block apply/revert.
