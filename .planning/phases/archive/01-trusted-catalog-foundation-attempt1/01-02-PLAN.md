## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keystroke input → in-memory filter | Search text is untrusted typing; it must never reach execution, paths, or registry writes |
| Restore offer dialog → bulk apply | Offer wording shapes user trust; confusion here causes skipped safety or blocked progress |
| Persisted journal → post-restart revert | Journal survives restarts; stale entries must still restore the correct captured priors |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Tampering | Search query handling | low | mitigate | Query is display-only filter input using OrdinalIgnoreCase StartsWith/Contains over titles; never executed, never interpolated into paths; SuggestionChosen cast guarded |
| T-01-06 | Spoofing | Restore-point offer copy | low | mitigate | Honest offer body states tweaks are already journaled for one-click revert so the point is optional; Skip path always present; apply never blocked on dialog outcome or creation failure |
| T-01-07 | Tampering | Journal retention across restarts | medium | mitigate | Entries carry TakenUtc; revert replays captured priors which remain the correct pre-apply values; journal cleared only after fully successful revert so repeat clicks are safe no-ops |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | Zero package installs in this phase; legitimacy gate not triggered; any future package addition must run the audit plus blocking human checkpoint before install |
</threat_model>
