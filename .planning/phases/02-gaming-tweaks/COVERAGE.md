# Phase 2: Gaming Tweaks — API Coverage Decision

No external API integration: the 6 D-06 network-dependent scripts (Plan 02-06) invoke pre-existing, fully-authored PowerShell logic that downloads installer binaries from `github.com/FR33THYFR33THY/Ultimate-Files` and official vendor domains (nvidia.com/amd.com/intel.com) via plain `Invoke-WebRequest`/direct download calls already written into the source scripts — this phase ports that download-and-run behavior byte-for-byte per source menu branch (D-06, "keep exactly as authored"), it does not design, call, or build against any new API surface, SDK, or service integration. There is no capability matrix to enumerate: the phase's job is running an already-authored installer script as-is via `IScriptRunner.RunEmbeddedScriptAsync`, the same embedded-resource-extract-and-run primitive Phase 1 already proved for Windows Defender's cab+ps1 payload, not building a client against `github.com`'s API or any vendor's API. No `Octokit`/GitHub REST API client is added (per CLAUDE.md's explicit "do not add Octokit.net" guidance), and no `HttpClient`-based download logic is written by this phase — every download is a subprocess spawn of the ported PowerShell content itself.
